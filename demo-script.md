# Northstar Final Demo Script

## Role

QA / Demo

## Demo Objective

Demonstrate the two core customer-support problems handled by
the Northstar prototype:

1. Order tracking
2. Returns

The demonstration uses scenarios that were previously executed
during QA testing.

All 12 Day 3 QA tests passed.

---

# 1. Introduction

### Action

Open the Northstar prototype.

### Say

"Hello everyone. I'm handling QA and Demo for the Northstar sprint.

During QA, I tested the customer-support flows using 12 realistic
customer questions covering order tracking, delayed orders,
returns, refunds, and vague customer requests.

All 12 tests passed.

I'll now demonstrate the main customer journeys supported by
the prototype."

---

# 2. Demo — Normal Order Tracking

### Customer Input

"Where is my order?"

### Expected Behaviour

The system should recognize the order-status request and provide
the relevant order information.

### Say

"First, I'll demonstrate the order-tracking flow using a normal
customer question."

### After Response

"The system identifies the order-related request and provides the
relevant order-status information."

---

# 3. Demo — Delayed Order

### Customer Input

"My package is late. Can you check what's happening?"

### Expected Behaviour

The system should recognize the delayed-order situation and provide
the appropriate information.

### Say

"Next, I'll demonstrate a more specific delivery situation."

### After Response

"Here the system handles the delayed-order scenario and provides
the appropriate information."

"These scenarios were also verified during QA."

---

# 4. Demo — Return Request

### Customer Input

"How do I return something I bought?"

### Expected Behaviour

The system should recognize the return request and provide
appropriate return instructions.

### Say

"The second core area supported by Northstar is returns. I'll now
demonstrate a customer who wants to return an item."

### After Response

"The system recognizes that this is a return request and provides
the appropriate return guidance."

---

# 5. Demo — Refund

### Customer Input

"When will I get my refund?"

### Expected Behaviour

The system should provide appropriate refund information.

### Say

"The customer can also ask about their refund, and the system
provides the relevant information."

---

# 6. Demo — Informal Customer Input

### Customer Input

"where my order?"

### Expected Behaviour

The system should recognize the likely order-status intent or
appropriately request clarification.

### Say

"Finally, I'll demonstrate a less structured customer question.

Real customers won't always use perfectly written sentences, so
we included vague and informal inputs in our QA tests."

### After Response

"This scenario was included specifically to verify how the system
handles informal customer language."

---

# 7. QA Summary

### Say

"For QA, we created 12 customer scenarios covering order tracking,
delivery problems, returns, refunds, and vague customer input.

We executed all 12 tests, and all 12 passed.

The prototype is therefore ready for the final demonstration."

---

# End

Thank the audience and take questions.
