2. Work Rules & Commit Conventions
4-Hour Task Limit: No task card on the project board shall exceed 4 hours of estimated work. Larger tasks must be split into smaller, manageable chunks.
Same-Day Board Movement: Task statuses must be updated on the board on the day work occurs. No end-of-week batch updating.
Strict Commit Format: Every git commit must strictly follow this structure:
<type>: <what changed> - <why it matters>
(Examples: feat: add order status logic - enables automated lookup for ticket type 1, docs: draft FAQ copy - provides self-serve answers for refunds)
Generic commit messages like "wip", "update", or "changes" are prohibited and will be rejected.
3. Communication & Escalation Path
Daily Communication: Progress updates and blocker alerts will be shared daily via the team group messaging channel.
Inactivity Rule: Zero visible activity on the board or repository for 2 consecutive days triggers immediate escalation by the Team Lead.
Escalation Process:
Team Lead contacts the individual directly to check for blockers.
Unresolved tasks are re-assigned on the board within 12 hours to keep the project moving.
Escalation events are logged in the audit history for peer evaluation.
4. Work Boundaries
Team members must remain focused within their assigned role scope. If primary work is completed early, members must assist by picking up remaining unassigned board tasks rather than taking over another member's primary domain without board realignment.
